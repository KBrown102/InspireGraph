系统层的方法论，回答的是：**数值怎么定、系统之间怎么咬合、为什么玩久了还不崩**。做完玩法骨架后用它收口。

1. **四类平衡**：**传递平衡**（A > B > C，成本与强度同序）、**非传递平衡**（石头剪刀布的循环克制）、**挫折平衡**（表面不平衡但藏着反制，制造"学会后能翻盘"的深度）、**非对称平衡**（能力不同但胜率相当）。
2. **显性策略与退化策略**：Dominant strategy（一招鲜通吃）与 Degenerate equilibrium（让游戏变无聊的稳定态）都是设计缺陷，要预先识别并留反制。Sirlin《Playing to Win》的用处就是区分**健康的精通**与**退化的玩法**。
3. **源汇模型 sink / faucet**：任何虚拟经济先画源（资源从哪进来）与汇（资源到哪去），二者必须在目标时长内平衡；用基尼系数看贫富分布是否健康。
4. **保底机制 pity system**：概率奖励必须在 N 次内兑现，避免长尾挫败把人劝退。
5. **三类调参旋钮**：**手感旋钮**（攻速 / 移速 / 动画时序，靠试玩直觉调）、**曲线旋钮**（成长需求 / 数值缩放 / 成本系数，靠数学建模调）、**门槛旋钮**（等级要求 / 资源阈值 / 冷却，靠时长目标调）。**旋钮必须外置到数据文件，禁止硬编码**，并记录取值范围与当前取值的理由。
6. **嵌套循环模型**：**微循环**（约 30 秒，动作本身就爽）、**中循环**（5–15 分钟，目标—奖励闭环）、**宏循环**（单次会话：进度 + 自然停点 + 回归理由）。每个机制至少要挂上其中一个循环，挂不上就是冗余。
7. **系统动力学**：画**增强回路**（增长引擎）与**平衡回路**（稳定机制）。沙盒 / 经营类的玩法张力正来自这两者互相拉扯。
8. **数值曲线**：线性（稳定增长）、二次（加速）、对数（递减回报）、S 曲线（慢起—快中—见顶）。用 **TTK / TTC**（击杀时间 / 完成时间）当主锚点，其余数值从它倒推。
9. **垂直切片 vertical slice**：做一小段但美术 / 音效 / UI 都达到最终质量的完整纵切，用来验证"这方向值不值得做下去"，优于横向铺开一堆半成品。

设计启示（接我们项目）：
- **每日小游戏**：一个微循环 + 一个中循环就够，不要上宏循环；旋钮全部外置到文件顶部常量区（方便改数值重玩、也方便玩家自己折腾）；治愈向要避开显性策略（别让一种玩法碾压其他）。
- **直播互动（巴别塔）**：TTK 先钉死，其余数值从它倒推；礼物与积分走经典的源汇模型，防止通胀；保底机制必须有，避免氪金与非氪体验断崖。
- **沙盒类（蚁界）**：靠增强回路（蚁群扩张）与平衡回路（食物短缺 / 灾害）的张力造玩法；事件系统（降雨 / 陨石 / 入侵）需要正经做 sink / faucet 建模，否则要么毫无压力要么一波团灭。
- **通用自检**：这个机制的旋钮是哪一类、放在哪？它挂在哪个循环上？有没有一招鲜能碾过去？
